# Готовые файлы для чтения и загрузки

Эта папка — материалы для ручного показа. Это **не каталог автоматических тестов** `tests/` и не база, которую программа сама перечитывает при каждом вопросе. Все материалы вымышлены и подготовлены для БВТ2506, а не взяты из внутренних систем Сбера.

## Где исходная база

[../../data/documents.json](../../data/documents.json) содержит 13 исходных записей; после выбора последних версий остаются 12 активных разделов. При первом запуске с **новым** файлом SQLite они автоматически попадают в базу. Загружать их руками для начала показа не нужно.

В `01-reference/` лежат читаемые копии этих 12 активных записей. Это справочная папка: откройте Markdown на GitHub или в редакторе и посмотрите текст, права, приоритет и ответственного. Здесь намеренно присутствуют памятка меньшего приоритета и две противоречащие инструкции эскалации: они нужны для демонстрации выбора источника и конфликта.

Сам `data/documents.json` — **массив** документов. Его нельзя отправить в загрузчик JSON как одну инструкцию: загрузчик ожидает **один JSON-объект**, например файл из `03-updates/`.

Изменение файлов в GitHub само по себе не публикует их в вашей уже созданной SQLite-базе. Для добавления на показе используйте «Документы → Предложить инструкцию → Отправить на проверку» и утверждение тимлидом. Если нужна исходная база заново, запускайте показ с отдельным новым `KB_DB`, как описано в руководстве демонстрации; рабочую базу удалять не требуется.

## Что выбрать для основного показа

Начните с [02-upload/01-vpn-telemetry.txt](02-upload/01-vpn-telemetry.txt). Это обычный текстовый файл с новой операцией, которой нет в исходном корпусе. В TXT оставлен только порядок действий; название вводится в форме, а учебный характер материала указан здесь и в интерфейсе.

1. В системе **«Учебный VPN»** спросите: **«Как выполнить калибровку телеметрии?»** В чистой исходной базе подтверждённого ответа нет.
2. Предложите этот TXT от имени стажёра, заполнив метаданные ниже. Пока предложение ожидает решения, ответ не меняется.
3. Переключитесь на **«Тимлид ИБ»**, откройте вкладку **«Согласование»**, проверьте текст и права и нажмите **«Утвердить»**.
4. Вернитесь к стажёру и повторите вопрос. Источник — `demo-vpn-telemetry@1#section-001`, в инструкции есть **ТЕЛЕМЕТРИЯ-21**. Откройте источник и покажите цитату.

Нажатие «Отправить на проверку» ещё не делает документ доступным для ответов. Повторное использование того же id/version после публикации не является обновлением: для обновления нужна большая версия. Для повторной репетиции проще взять новую отдельную базу показа.

## Поля формы для обычных файлов

Для TXT, MD, DOCX и PDF тело файла — это текст инструкции. Права, версия, система и тема задаются **отдельно в форме**. Строка «Система» не определяется автоматически по слову VPN в документе.

Для четырёх обычных файлов общие значения:

| Поле в интерфейсе | Значение |
|---|---|
| Система (идентификатор) | `vpn` |
| Ответственный | `Служба сетевой поддержки` |
| Версия | `1` |
| Приоритет | `30` |

Остальные поля заполните по строке выбранного файла:

| Файл | Название | Идентификатор документа | Тема/операция | Кому доступно |
|---|---|---|---|---|
| [01-vpn-telemetry.txt](02-upload/01-vpn-telemetry.txt) | Калибровка телеметрии учебного VPN | `demo-vpn-telemetry` | `vpn-telemetry-calibration` | Стажёр ИБ **и** Стажёр поддержки |
| [02-vpn-route-selftest.md](02-upload/02-vpn-route-selftest.md) | Самодиагностика маршрутизации учебного VPN | `demo-vpn-route-selftest` | `vpn-route-selftest` | Стажёр ИБ **и** Стажёр поддержки |
| [03-vpn-connector-attestation.docx](02-upload/03-vpn-connector-attestation.docx) | Аттестация коннектора учебного VPN | `demo-vpn-connector` | `vpn-connector-attestation` | Только Стажёр ИБ |
| [04-vpn-gateway-fingerprint.pdf](02-upload/04-vpn-gateway-fingerprint.pdf) | Сверка отпечатка шлюза учебного VPN | `demo-vpn-gateway` | `vpn-gateway-fingerprint` | Стажёр ИБ **и** Стажёр поддержки |

Поле «Тема/операция» заполните явно, не оставляйте `new-instruction`. Одно имя темы означает одну операцию. Для другой операции используйте другое имя; сопоставляемые инструкции одной операции должны иметь одинаковую тему.

## Вопросы и проверяемые признаки

Все вопросы ниже задаются в системе **«Учебный VPN»**. Для сопоставимого испытания начните с чистой базы и без предыдущих вопросов в диалоге.

| Формат | Вопрос | После утверждения должно быть в источнике |
|---|---|---|
| TXT | Как выполнить калибровку телеметрии? | `ТЕЛЕМЕТРИЯ-21` |
| MD | Как выполнить самодиагностику маршрутизации? | `МАРШРУТ-26` |
| DOCX | Как выполнить аттестацию коннектора? | `КОННЕКТОР-32`, доступ только ИБ |
| PDF | Как сверить отпечаток шлюза? | `ШЛЮЗ-43` |
| JSON | Как выполнить архивацию протокола диагностики? | `АРХИВ-54` |

Для DOCX покажите один вопрос от двух профилей: ИБ получает материал, поддержка — отсутствие подтверждённого ответа. Закрытый маркер и ссылка не должны раскрываться поддержке. PDF содержит настоящий извлекаемый кириллический текст, а не скан: OCR для этого примера не нужен.

Это пять **разных** новых инструкций с отдельными id. Их можно опубликовать в одной учебной базе. Для краткого показа достаточно одного TXT, остальные пригодятся для проверки форматов. Формулировка LLM может отличаться; оценивайте наличие нужных действий и доступного источника, а не дословное совпадение свободного текста. В режиме «Поиск по инструкциям» LLM не вызывается.

## Готовый JSON без ручного заполнения метаданных

[02-upload/05-vpn-diagnostics-archive.json](02-upload/05-vpn-diagnostics-archive.json) уже содержит `id`, `rule`, `version`, `priority`, `roles`, `area`, `contact` и `sections` с темой. Выберите его в загрузчике и нажмите «Отправить на проверку». Метаданные берутся из **самого JSON**; значения обычных полей формы их не заменяют.

Файл подходит для демонстрации того же цикла: стажёр предлагает → до решения ответа нет → тимлид утверждает → вопрос об архивации получает источник `demo-vpn-archive@1#procedure` с `АРХИВ-54`.

## Новая версия и отклонение

Эти два файла относятся к системе **«Реестр инцидентов»**, не к VPN.

| Файл | Что сделать | Что проверить |
|---|---|---|
| [03-updates/01-access-v3-approve.json](03-updates/01-access-v3-approve.json) | Предложить, затем утвердить тимлидом | Источник меняется с `access@2#request` на `access@3#request`, появляется `КУРС-03`; v2 больше не открывается |
| [03-updates/02-access-v4-reject.json](03-updates/02-access-v4-reject.json) | Предложить **после v3**, затем отклонить | Укажите причину `Не описано согласование руководителем`; ответ остаётся по v3 с `КУРС-03`, `КУРС-04` в ответ не попадает |

Вопрос: **«Как получить доступ к реестру?»**. Файл v4 намеренно неполный: в нём указан код, но не описано согласование. Это пример предложения, которое редактор не должен публиковать. Если случайно утвердить v4, база действительно изменится — для следующего показа понадобится новая отдельная учебная база.

## Создать собственную инструкцию

Можно написать небольшой TXT/MD в UTF-8, сохранить DOCX либо экспортировать документ в PDF с текстовым слоем. Одна инструкция должна описывать понятную операцию: кто выполняет, куда заходит, какие поля заполняет, что подтверждает успех и к кому обращаться при затруднении. Для учебного показа используйте вымышленные системы и значения.

Задайте стабильный id, понятное название, систему, права, приоритет и ответственного. Для обновления сохраните id и увеличьте версию. После извлечения текста и проверки тимлидом материал станет доступен для retrieval. **Это пополнение базы знаний, не обучение Qwen на файле.**

## Проверка и повторная генерация материалов

[manifest.json](manifest.json) — машиночитаемая таблица всех файлов, метаданных и ожидаемых признаков. Для проверки готовых файлов из корня проекта:

```bash
.venv/bin/python demo/files/verify_materials.py
```

Проверка использует настоящий импортёр и временные SQLite-базы. Для всех пяти форматов проверяется отсутствие ответа до публикации, наличие после неё, маркер и источник; отдельно — права DOCX, публикация v3 и отклонение v4. Ваша рабочая база не меняется. Модель не вызывается: это проверка загрузки/публикации/поиска, а не качества генерации.

Готовые DOCX и PDF уже находятся в репозитории; создавать их заново перед показом не нужно. Для разработчика есть [build_materials.py](build_materials.py). Дополнительные инструменты генерации, не требующиеся приложению: `python-docx` и `reportlab` (проверены 1.2.0 и 4.4.9). PDF использует шрифт DejaVu Sans; иной путь можно передать через переменную `DEMO_FONT`.
