# Как добавить документ и где потом его искать

## Откуда брать файлы

Для защиты используйте [готовую папку files](files/README.md): там есть читаемые исходные инструкции, новые файлы для загрузки и примеры обновления. Все материалы вымышлены. Не нужно получать доступ к внутренней документации Сбера, чтобы запустить учебный показ.

Для пополнения корпуса команда сама готовит реалистичные учебные инструкции. Михаил проверяет сценарий и требования, Даниил оформляет данные и метаданные, Гоша готовит контрольные вопросы и проверяет поиск. Новый материал утверждает тимлид. Публичные руководства ПО можно использовать как источник идей с указанием происхождения, но вымышленные банковские процедуры нужно обозначать как учебные, а не выдавать за реальные регламенты.

Можно написать текст в редакторе и сохранить UTF-8 `.txt`/`.md`, создать `.docx` в Word/LibreOffice либо экспортировать текстовый PDF. Скан или фотография страницы требуют OCR вне текущего приложения.

Для начала готовьте короткий документ по одной операции, без большой служебной шапки и повторяющихся заголовков. Название и права задаются в метаданных. Маленькая модель может неверно выбрать цитату из шумного текста; приложение отклонит такой ответ. Основной TXT-пример содержит только процедуру, а учебный характер указан в README и интерфейсе.

После `git clone` папка `demo/files` уже находится на вашем диске. В загрузчике выберите файл именно оттуда. Если открыли файл на GitHub в браузере, сначала скачайте его кнопкой Download/Raw либо скачайте весь проект через Code → Download ZIP на нужной ветке. Вставка GitHub-ссылки в чат не загружает документ: загрузчик принимает локальный файл.

## Порядок для любого файла

1. Откройте приложение, выберите систему и профиль сотрудника.
2. Сначала задайте проверочный вопрос — зафиксируйте исходный ответ.
3. Перейдите на вкладку **«Документы»**.
4. Нажмите поле **«Файл инструкции»**, выберите **один** файл на своём компьютере из `demo/files/02-upload`.
5. Для обычного файла заполните метаданные по таблице в `files/README.md` или `files/manifest.json`. Для готового JSON применяются поля самого файла.
6. Нажмите **«Отправить на проверку»**. Должно появиться сообщение с номером предложения. Это ещё не публикация.
7. Вернитесь в **«Помощник»** и повторите вопрос: до утверждения новый материал не используется.
8. Выберите **«Тимлид ИБ»**, откройте вкладку **«Согласование»**, разверните нужное предложение по названию и версии. Номер не обязан быть №1.
9. Проверьте автора, систему, роли, приоритет, извлечённый текст и возможные пересечения с действующими источниками. Нажмите **«Утвердить»**.
10. Вернитесь в профиль сотрудника, **выберите систему документа** и задайте вопрос заново. После публикации прежняя история очищается; ответ сам не появляется без нового вопроса.
11. Откройте источник и найдите контрольный маркер. Так видно, что использован именно новый материал.

Для основного показа подходит TXT из первой строки [таблицы файлов](files/README.md). Все пять новых примеров загружать подряд не требуется. Остальные форматы можно показать на репетиции или при вопросе преподавателя.

## Что заполнять в форме для TXT/MD/PDF/DOCX

| Поле интерфейса | Смысл |
|---|---|
| Название | Человеческое название инструкции |
| Идентификатор документа | Стабильный `id`: до 48 латинских строчных букв/цифр, `-`, `_` |
| Система (идентификатор) | `реестр`, `siem`, `vpn` либо согласованный новый идентификатор |
| Ответственный | Реально указанный в учебном материале контакт/подразделение |
| Версия | 1 для нового `id`; при обновлении того же `id` больше прежней |
| Приоритет | 1–100; большее число имеет преимущество в одной теме |
| Кому доступно | «Стажёр ИБ» (`ib`) и/или «Стажёр поддержки» (`support`) |
| Тема/операция | Идентификатор одной операции; для сравниваемых документов укажите одинаковый |

**Вручную заполните и «Идентификатор документа», и «Тема/операция».** Изменение первого поля внутри формы не означает, что второе автоматически обновилось. Точные значения готовых примеров находятся в manifest.

Тимлид не указывается как читатель `lead`: он читает с правами `ib`, а утверждение — отдельное полномочие. Роли не определяются автоматически по тексту PDF или DOCX. Например, DOCX, задуманный только для ИБ, станет таким только при правильном выборе поля «Кому доступно» и проверке тимлидом.

Для знакомой операции реестра используйте её существующую тему: доступ на чтение — `access-read`, статус заявки — `request-status`. Инструкция с произвольной новой темой не обязательно изменит ответ на знакомый вопрос: в реестре есть дополнительная проверка типа операции. Для обновления доступа проще использовать подготовленный JSON с тем же id и правильной темой.

У новой системы ещё нет опубликованных документов — она не появится в доступном сотруднику списке сразу после предложения. После утверждения выберите её в боковой панели; вопрос по VPN в выбранном реестре не ищется по всей базе.

## Чем отличается подготовленный JSON

JSON содержит текст и все метаданные: `id`, `version`, `priority`, `roles`, `area`, `rule`, массив `sections`; внутри каждого раздела — `key`, `text`, `topic`, при необходимости `facts`. То есть тема и факты записываются как `sections[].topic` и `sections[].facts`, а не отдельными полями верхнего уровня. Для JSON дополнительные поля формы игнорируются. Поэтому изменение роли в форме не изменяет роль внутри загруженного JSON — нужно править сам JSON до загрузки.

Готовый JSON удобен для версии доступа и показа приоритетов/фактов. Формат описан в [`docs/data-format.md`](../docs/data-format.md). Один файл — один объект-инструкция, не массив корпуса и не `manifest.json`.

## Обновление и отклонение

Для новой версии сохраняйте прежний `id` и повышайте `version`. Одинаковое название с другим `id` считается другим документом. Добавление копии с новым `id`, темой и тем же текстом не заменяет старую версию.

Для показа загрузите `files/03-updates/01-access-v3-approve.json`, утвердите, спросите о доступе и проверьте `КУРС-03`. Затем загрузите `02-access-v4-reject.json`, у тимлида заполните **«Причина отклонения»** и нажмите **«Отклонить»**. После этого действует v3, а не v4. Причина остаётся в **«Истории решений»**.

Утверждение той же или меньшей версии не пройдёт. Не повышайте номер наугад для повторения сценария: новая репетиция с отдельной базой вернёт исходную v2 без удаления рабочей истории.

## Что сохраняется

На GitHub и в `demo/files` лежат подготовленные исходники. Сайт не создаёт там копию вашего PDF. Извлечённый текст, метаданные, предложение и решение сохраняются в SQLite текущего запуска. После утверждения меняется опубликованный снимок; в Elasticsearch-режиме это приводит к использованию нового индекса по хешу содержимого. Старые индексы автоматически не удаляются.

Кнопка источника открывает сохранённый раздел. Чтобы иметь оригинальные бинарные файлы для отчёта, команда отдельно хранит их в своей согласованной папке. Не добавляйте в публичный репозиторий реальные закрытые инструкции или `.local` с пользователями.

## Ограничения

Файл — до 5 МиБ, извлечённый текст — до 60 000 символов, до 30 разделов на документ, текст раздела — до 5000 символов. Авторазбиение обычного файла делает фрагменты до 2500 символов с перекрытием; при слишком большом количестве разделов разделите материал на несколько инструкций. Снимок стенда ограничен 1000 действующих разделов.

PDF нужен без пароля и с текстовым слоем, до 100 страниц; сложные таблицы могут извлекаться неточно. TXT/MD сохраняйте в UTF-8. После парсинга тимлид проверяет, что формулировки, числа и порядок шагов не исказились.
