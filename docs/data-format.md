# Данные и публикация

Вкладка **Документы** принимает PDF с текстовым слоем, DOCX, UTF-8 TXT/MD и структурированный JSON. Максимум файла — 5 МиБ, текста — 60 000 символов; сканированный PDF требует предварительного OCR. Из DOCX читаются параграфы и таблицы в порядке документа. Автоматическое извлечение сложных таблиц PDF может терять структуру — результат нужно проверять.

Для обычного файла заполните название, стабильный id, систему, версию, приоритет, роли и тему операции. Текст автоматически разбивается на перекрывающиеся фрагменты до 2500 символов. Для подготовленного JSON используются метаданные самого файла.

```json
{
  "id": "access",
  "rule": "access",
  "version": 3,
  "priority": 30,
  "title": "Доступ к реестру инцидентов",
  "contact": "Служба сопровождения учебного реестра",
  "roles": ["ib", "support"],
  "area": "реестр",
  "sections": [{
    "key": "request",
    "topic": "access-read",
    "text": "Откройте портал и отправьте заявку руководителю."
  }]
}
```

- Новая версия имеет тот же `id` и больший `version`. Активна последняя опубликованная версия.
- `area` — идентификатор системы. Учебные значения `реестр`, `siem`, `vpn`; можно добавить собственное значение из строчных букв, цифр, дефисов и подчёркиваний.
- `roles` — `ib`, `support` либо обе роли. Вложенный раздел не может переопределить права, область или приоритет документа.
- `topic` — идентификатор **одной операции**, общий для сопоставляемых источников. Для нового материала возможна своя тема. У старых записей `rule` сопоставляется теме через `kb/topics.py`.
- `priority` — 1–100, большее значение имеет преимущество внутри одной темы.
- До 30 разделов, каждый до 5000 символов. На демонстрационный снимок — до 1000 активных разделов.

Загрузка создаёт предложение. Пока тимлид не утвердил его, оно не участвует в поиске. Тимлид видит автора, метаданные и текст, сверяет с текущими источниками и утверждает либо отклоняет с причиной. Сохраняются автор, проверяющий, время и состояние. Права назначаются редактором, а не языковой моделью.

## Противоречия

Для проверяемых утверждений используйте `facts`:

```json
{
  "key": "limit",
  "topic": "incident-escalate",
  "text": "Срок эскалации критического инцидента — 15 минут.",
  "facts": {"deadline_minutes": "15"}
}
```

Разные значения одного факта в равноприоритетных источниках одной темы дают явный конфликт. Разные тексты без достаточной разметки требуют сверки редактора. Модель также получает инструкцию сообщать о несовместимых указаниях, но её семантическое решение не гарантированно.

Темы и факты размечает человек. Ошибочная разметка может скрыть реальное противоречие либо вызвать лишний запрос на сверку. Обязательное утверждение нового материала остаётся границей публикации.

Источник: `id@version#section`. При открытии повторно проверяются роль, выбранная система и актуальность версии. Старый источник после обновления недоступен. История чата очищается при изменении опубликованного снимка.
