# Техническое задание учебного прототипа

Команда БВТ2506. Основание: карточка проекта 3 и встреча с преподавателем от 12 октября 2026 года. Все материалы синтетические, система не представляет реальные инструкции Сбера.

## Пользователь и задача

Стажёр или младший специалист ИБ задаёт вопрос о внутренних программах условного банка. Ассистент выдаёт конкретные действия и разрешённые источники. Поддержка клиентов по банковским переводам в MVP не входит.

Учебные системы: реестр инцидентов, SIEM, VPN. Роли: стажёр ИБ, стажёр поддержки, тимлид ИБ. Права профилей намеренно небольшие и понятные для показа; тимлид отдельно утверждает документы.

## Обязательная часть карточки проекта

Загрузка документов → чанкинг → индекс Elasticsearch → классические методы NLP (TF-IDF, дополнительный эксперимент FastText) → релевантные фрагменты → ответ/источники. Интерфейс — Streamlit. Отдельный отчёт — precision@k и recall@k.

Режим «Поиск по инструкциям» показывает классический контур без языковой модели. Режим «ИИ-ответ» применяет LLM поверх отобранных фрагментов. Эта версия добавляет LLM по запросу команды; обязательность внешнего API на встрече не фиксировалась.

## Поведение

1. Ответ по действующей инструкции с цитируемыми шагами и открываемым источником.
2. Доступ проверяется до передачи контекста модели и повторно при открытии источника. История очищается при смене пользователя, профиля, системы, режима или опубликованного снимка.
3. Среди источников одной операции действует приоритет. В ответе доступно объяснение выбора. Явные несовпадающие размеченные факты равноприоритетных документов ведут к конфликту; непроверенные различия — к сверке редактора.
4. При недостатке сведений ассистент сообщает об этом и указывает известного ответственного; контакт не придумывает модель.
5. Новая инструкция сохраняется как предложение. Только тимлид может опубликовать её либо отклонить с причиной. Автор и решение сохраняются.
6. Поддерживаются UTF-8 TXT/MD, PDF с текстовым слоем, DOCX и структурированный JSON. OCR не входит в MVP. Лимиты: файл 5 МиБ, текст 60 000 символов, до 30 разделов, до 1000 активных разделов на стенд.
7. Локальный режим использует локальную LLM, SQLite и локальный retrieval либо Elasticsearch. GigaChat — отдельный режим с явным разрешением внешней сети; проверка TLS не отключается.

## Демонстрация и приёмка

| Случай | Ожидаемый результат |
|---|---|
| Получение доступа | Порядок действий и действующий разрешённый источник |
| Отзыв/администраторский доступ без инструкции | Сообщение об отсутствии подтверждённого ответа |
| Два действия | Ответ по частям, все использованные источники |
| Равноприоритетное противоречие | Передача тимлиду без выбора неподтверждённого значения |
| Один вопрос от ИБ и поддержки | Закрытые фрагменты не передаются модели и не раскрываются в источниках/истории |
| Загрузка новой версии | До утверждения ответ прежний, после — по новой версии |
| Отклонение | Старая инструкция остаётся, причина сохраняется |
| Модель недоступна | Понятная ошибка; NLP-ответ не выдаётся за генерацию |

Командные ориентиры для учебного корпуса: Recall@3 ≥ 0,9, Precision@3 ≥ 0,3 при одном эталонном источнике, корректные отказы на согласованных негативных примерах. Эти численные цели предложены для проекта и не являются зафиксированными нормативами заказчика. Для LLM дополнительно проверяются источники, цитаты, полнота действий, неподтверждённые утверждения и время ответа. Проверка цитат не доказывает правильность всего пересказа.

## Стартовая конфигурация

Для испытаний полного стенда с небольшой CPU-моделью: 4 vCPU, 8 ГиБ RAM, 20 ГиБ диска. Это план конфигурации для замера, а не доказанный минимум. Отдельно измеряются retrieval и полный ответ с LLM; скорость локального поиска не подменяет скорость генерации. Фактические результаты и ограничения публикуются в отчёте о качестве.
